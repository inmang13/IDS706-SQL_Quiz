[1] Assignment instructions
---------------------------
This is assignment 7: Imagine you are a TA. You need a short SQL quiz that
students can take against a real database: they sign in, write a query, run
it, and see the result.

In the in-class lab you connected Python to Postgres (in Supabase). This
assignment asks you to build a small system: a hosted database, sign-in,
automation, and a SQL quiz that runs against live data.

What you must build

All four items are required.

A hosted PostgreSQL database. A free Supabase project is recommended. Another
hosted Postgres service is acceptable.

Authentication. Use Supabase Auth or similar (like Clerk). Signed-out users
cannot save a quiz and cannot run a query. Signed-in users may do both.

GitHub Actions with Github Secrets.

A SQL quiz worth 20 points.

You choose the topic. That topic determines what data you insert into the
database.
Every question is a SQL question: write a query, or state what a query returns.
Point values must sum to 20. Five questions at 4 points each is acceptable;
other splits are acceptable.
Each question should include a hint: the expected SQL and the expected result.
A signed-in user must be able to run SQL against the database and see the
result table.
Treat this as a TA would: you write the questions; someone else signs in and
answers them by querying.

Completion

A classmate (or you) can sign in, open a question, enter SQL, run it, and see
rows from your database.
GitHub Actions shows a successful run that used the secret. A password must not
be pasted into the workflow file.

Optional extra credit

Not required.

Queries use parameters rather than f-string SQL (safe from injection).
An audit log of who ran or saved what.
An integrity check so the taker role cannot edit that log.

Submission

Submit the URL of your GitHub repository. The repository README must include
the URL of your quiz site and must be detailed enough for another person to
understand how the system is set up and how to use it.

Evaluation

All four required items must be present. We mark the quiz by opening a
question, running SQL, and comparing the result to your hint. Extra credit is
awarded only if you implemented it. A password committed to git, or Actions
that never ran, means the system portion is incomplete.

Scoring details are on the Canvas rubric.

Notes

The application connects to Postgres over the network.
For Supabase, use the Session pooler (not the Direct connection) and
sslmode=require.
Keep .env on your machine and listed in .gitignore. CI must read GitHub
Secrets.
We assess the result set, not whether the taker reproduced your SQL
character-for-character.

Build Your Quiz Rubric
  Hosted database (20 pts): Complete = hosted database, data loaded, quiz
    clearly reads from it. Partial (10) = hosted database works, small setup
    quirks are fine. Not done (0) = no hosted database.
  Authentication (20 pts): Complete = sign-in works and gates save/query.
    Partial (10) = login exists but does not really restrict anything.
    Not done (0) = no sign-in.
  GitHub Actions (20 pts): Complete = green run; uses a secret; no password in
    the repo. Partial (10) = workflow exists but failed or did not connect.
    Not done (0) = no Actions.
  SQL quiz (25 pts): Complete = SQL questions, about 20 points, hints, Run
    shows live rows. Partial (15) = questions exist but Run is missing or it is
    not in the database. Not done (0) = no quiz.
  README (15 pts): Complete = quiz URL plus a usable write-up. Partial (8) =
    README exists but is thin or missing the URL. Not done (0) = no README.

[D2] Follow-up for color, answer sections, and autocomplete
-----------------------------------------------------------
Update the quiz page with these changes. Do not change how the page talks to
Supabase: keep the SUPABASE_URL and SUPABASE_ANON_KEY lines, sign-in, loading
questions, saving answers, and the run-sql call exactly as they are.

1. More color across the whole page
- Water-utility palette: deep navy top bar with white text, a light blue-gray
  page background, white cards for the question and results.
- Teal or bright blue for primary buttons (Run), a quieter outline style for
  Save.
- Colored status in the question list: grey = not started, amber = saved,
  green = correct. Show the points as a small colored chip.
- Result table: navy header row, light zebra striping, the ✓ match badge in
  green and "Not a match yet" in amber.
- Keep text high-contrast and make sure dark mode still works.

2. Split the hint into two separate collapsed sections, both closed by default,
   in this order:
- "Expected result" — the expected result table (from hint_result).
- "Answer (SQL)" — the expected SQL in a code block with a Copy button. Label
  it clearly as the answer, not a hint.
Opening one should not open the other.

3. SQL autocomplete in the editor
Replace the plain textarea with CodeMirror 5 loaded from cdnjs (no build step):
- https://cdnjs.cloudflare.com/ajax/libs/codemirror/5.65.16/codemirror.min.js
  and codemirror.min.css
- mode/sql/sql.min.js, addon/hint/show-hint.min.js,
  addon/hint/show-hint.min.css, addon/hint/sql-hint.min.js
Use mode "text/x-pgsql", line numbers, and syntax highlighting with a theme
that matches the page.
Give the SQL hint these tables so it suggests real names:
  pressure_zones: zone_id, zone_name
  mains: main_id, zone_id, material, diameter_in, length_ft, install_year
  crews: crew_id, crew_name, shift
  breaks: break_id, main_id, reported_at, break_type, cause, est_loss_gal
  repairs: repair_id, break_id, crew_id, started_at, completed_at,
           repair_method, cost_usd
Show suggestions automatically after typing 2+ letters, and also on
Ctrl+Space. Keep Ctrl/Cmd+Enter = Run.
When signed out, the editor stays read-only and greyed. Saved answers still
load into the editor, and Run and Save read the text from CodeMirror.
